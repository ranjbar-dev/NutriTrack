  <name>Task 1: Push subscription utility and PushSubscriptionControl component</name>
  <files>app/lib/push/subscription.ts, app/components/platform/PushSubscriptionControl.vue, tests/platform/push-subscription.spec.ts</files>
  <behavior>
    app/lib/push/subscription.ts:
    - Export type PushPermissionState = 'not-asked' | 'subscribed' | 'blocked' | 'unsupported'
    - Export function urlBase64ToUint8Array(base64String: string): Uint8Array
      - Standard implementation: pad base64 string, atob decode, convert to Uint8Array
    - Export async function getPushPermissionState(): Promise<PushPermissionState>
      - If 'PushManager' not in window || 'serviceWorker' not in navigator → return 'unsupported'
      - If Notification.permission === 'denied' → return 'blocked'
      - Get registration.pushManager.getSubscription(); if subscription !== null → return 'subscribed'
      - Return 'not-asked' (permission is 'default' or 'granted' but no active subscription)
    - Export async function subscribeToPush(vapidKey: string): Promise<PushSubscription | null>
      - If unsupported → return null
      - const registration = await navigator.serviceWorker.ready
      - Call registration.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: urlBase64ToUint8Array(vapidKey) })
      - Return PushSubscription object (caller may send to backend later)
      - On DOMException or NotAllowedError → return null (permission denied at prompt time)
    - Export async function unsubscribeFromPush(): Promise<boolean>
      - Get registration.pushManager.getSubscription(); if null → return true (already unsubscribed)
      - Call subscription.unsubscribe(); return result boolean

    PushSubscriptionControl:
    - No props; self-contained; reads VAPID key from useRuntimeConfig().public.vapidKey
    - On mount: call getPushPermissionState() to initialize permissionState ref
    - Renders based on permissionState:
      - 'not-asked': "دریافت اعلان‌ها را فعال کنید" primary button → on click call subscribeToPush → update state
      - 'subscribed': "اعلان‌ها فعال است ✓" label + "غیرفعال کردن" secondary button → on click call unsubscribeFromPush → set state to 'not-asked'
      - 'blocked': InlineNotice with "اعلان‌ها مسدود شده‌اند — تنظیمات مرورگر را بررسی کنید" (no CTA)
      - 'unsupported': InlineNotice with "مرورگر شما از اعلان‌ها پشتیبانی نمی‌کند" (no CTA, no error styling)
    - Loading state during subscribe/unsubscribe: button disabled with spinner
    - After subscribeToPush returns null (denied at prompt): re-call getPushPermissionState to get 'blocked'

    Tests in tests/platform/push-subscription.spec.ts:
    - Mock navigator properties for each test case
    - Test getPushPermissionState: unsupported environment → 'unsupported'; Notification.permission=denied → 'blocked'; existing subscription → 'subscribed'; no subscription, permission=default → 'not-asked'
    - Test subscribeToPush: mocked pushManager.subscribe resolves → returns PushSubscription; DOMException thrown → returns null
    - Test unsubscribeFromPush: existing subscription unsubscribes; null subscription returns true immediately
    - Test PushSubscriptionControl renders correct UI for each state (mount with mocked getPushPermissionState)
  </behavior>
