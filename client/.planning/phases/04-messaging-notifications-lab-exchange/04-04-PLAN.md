    - Upload state: type LabUploadState = 'idle' | 'uploading' | 'success' | 'failure'
    - Form fields:
      - title (required string input — Persian placeholder "عنوان آزمایش")
      - result_type (select dropdown, options from above Persian map)
      - test_date (optional date input, YYYY-MM-DD format)

      - Success → set state 'success', emit uploaded(result), reset form after 1.5s, emit close
      - Error → set state 'failure', show Persian error message + retry button
      - Retry → reset state to 'idle', re-enable form

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LabUploadSheet → uploadLabResult | User-supplied file data and metadata cross client→API |
| LabResultItem → window.open | URL from API response is opened in browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-01 | Tampering | LabUploadSheet file input | mitigate | Validate file.size ≤ 10MB and file.type in [application/pdf, image/jpeg, image/png] before FormData submission |
| T-04-04-02 | Information Disclosure | LabResultItem window.open(downloadUrl) | accept | Download URL requires auth token (enforced by backend); frontend opens the authenticated download endpoint |
| T-04-04-03 | Information Disclosure | LabResultItem window.open(result.link) | accept | External link is provided by the authenticated API; frontend opens it in _blank with no referrer injection needed |
| T-04-04-04 | Elevation of Privilege | /nutritionist/clients/:id/labs route | mitigate | role-shell middleware from Phase 2 blocks client users from accessing nutritionist routes |
</threat_model>
