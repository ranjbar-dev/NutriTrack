**backend/db/queries/foods.sql** — Write all sqlc-annotated queries:

1. `CreateFood` (:one) — INSERT into foods table. Accept name, description, calories, protein_g, carbs_g, fat_g, fiber_g, sugar_g, sodium_mg, measurement_unit, measurement_amount, created_by. Compute `name_normalized = LOWER(normalize_persian(name))`. RETURNING *.

2. `AddFoodCategory` (:exec) — INSERT into food_categories (food_id, category). Use ON CONFLICT DO NOTHING to handle duplicates.

3. `GetFoodByID` (:one) — SELECT f.*, u.full_name as creator_name FROM foods f JOIN users u ON f.created_by = u.id WHERE f.id = $1.

4. `GetFoodCategories` (:many) — SELECT category FROM food_categories WHERE food_id = $1.

5. `ListFoods` (:many) — Complex query with optional search, category filter, active filter, pagination:
   ```sql
   SELECT f.*, u.full_name as creator_name
   FROM foods f
   JOIN users u ON f.created_by = u.id
   WHERE f.is_active = COALESCE(sqlc.narg('is_active'), true)
     AND (sqlc.narg('search')::text IS NULL 
       OR f.name_normalized ILIKE '%' || LOWER(normalize_persian(sqlc.narg('search')::text)) || '%')
     AND (sqlc.narg('category')::food_category IS NULL 
       OR EXISTS (SELECT 1 FROM food_categories fc WHERE fc.food_id = f.id AND fc.category = sqlc.narg('category')::food_category))
   ORDER BY 
     CASE WHEN sqlc.narg('search')::text IS NOT NULL 
       THEN similarity(f.name_normalized, LOWER(normalize_persian(sqlc.narg('search')::text)))
       ELSE 0 END DESC,
     f.created_at DESC
   LIMIT sqlc.arg('limit_val')
   OFFSET sqlc.arg('offset_val');
   ```

6. `CountFoods` (:one) — Same WHERE clause as ListFoods but SELECT COUNT(*). Used for pagination `has_more` calculation.

7. `UpdateFood` (:one) — UPDATE foods SET name=$2, name_normalized=LOWER(normalize_persian($2)), description=$3, calories=$4, protein_g=$5, carbs_g=$6, fat_g=$7, fiber_g=$8, sugar_g=$9, sodium_mg=$10, measurement_unit=$11, measurement_amount=$12, updated_at=NOW() WHERE id=$1 RETURNING *.

8. `SoftDeleteFood` (:exec) — UPDATE foods SET is_active=false, updated_at=NOW() WHERE id=$1.

9. `SoftDeleteFoodByOwner` (:exec) — UPDATE foods SET is_active=false, updated_at=NOW() WHERE id=$1 AND created_by=$2. Used for row-level auth for nutritionists (per D-29).

10. `DeleteFoodCategories` (:exec) — DELETE FROM food_categories WHERE food_id=$1. Used before re-inserting categories on update.

11. `CheckDuplicateFoodName` (:one) — SELECT EXISTS(SELECT 1 FROM foods WHERE LOWER(normalize_persian(name)) = LOWER(normalize_persian($1)) AND is_active = true AND id != sqlc.narg('exclude_id')::uuid) AS is_duplicate. Per D-33.

12. `CountActiveFoods` (:one) — SELECT COUNT(*) FROM foods WHERE is_active = true. For admin stats (ADMIN-08).

After writing queries, run `sqlc generate` from the `backend/` directory to generate Go code.

   - Call `foodRepo.GetCategories(id)`

3. `ListFoods(ctx, search *string, category *string, isActive *bool, page, limit int) (*dto.FoodListResponse, error)`:
   - Default page=1, limit=20 (per D-14). Cap limit at 100.
   - Calculate offset = (page - 1) * limit
   - Call `foodRepo.List()` and `foodRepo.Count()` with same filter params
   - For each food in list, fetch categories via `foodRepo.GetCategories()`

Endpoints:

1. `Create(c *gin.Context)` — POST /api/foods
   - Bind JSON to `dto.CreateFoodRequest`. On error: 400 + `"اطلاعات ورودی نامعتبر است"`
   - Get `user_id` from gin context (set by Auth middleware): `c.GetString("user_id")`, parse as UUID
   - Call `foodService.CreateFood(ctx, userID, req)`
   - If duplicate name error, return 409 + the Persian error message
   - On success: 201 + FoodResponse

2. `Get(c *gin.Context)` — GET /api/foods/:id
   - Parse `id` param as UUID. On error: 400 + `"شناسه نامعتبر است"`
   - Call `foodService.GetFood(ctx, id)`
   - If not found: 404 + `"غذا یافت نشد"`
   - On success: 200 + FoodResponse

3. `List(c *gin.Context)` — GET /api/foods
   - Parse query params per D-30: `search` (string), `category` (string), `is_active` (bool, default true), `page` (int, default 1), `limit` (int, default 20)
   - Call `foodService.ListFoods(ctx, search, category, isActive, page, limit)`
   - On success: 200 + FoodListResponse

4. `Update(c *gin.Context)` — PUT /api/foods/:id
   - Parse `id` param, bind JSON to `dto.UpdateFoodRequest`
   - Get `user_id` and `role` from context
   - Call `foodService.UpdateFood(ctx, id, userID, role, req)`
   - Handle authorization errors: 403 + `"شما مجوز ویرایش این غذا را ندارید"` (per D-29)
   - Handle duplicate name: 409
   - On success: 200 + FoodResponse

5. `Delete(c *gin.Context)` — DELETE /api/foods/:id
   - Parse `id`, get `user_id` and `role` from context
   - Call `foodService.DeleteFood(ctx, id, userID, role)`
   - Handle authorization errors: 403 + `"شما مجوز حذف این غذا را ندارید"`
   - On success: 200 + `{"message": "غذا با موفقیت حذف شد"}`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client/Nutritionist → /api/foods | Untrusted input: food names, nutritional values, categories |
| Nutritionist → DELETE/UPDATE | Row-level auth: nutritionist can only modify own items |
| Super Admin → DELETE/UPDATE | Privileged: can modify any item |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Spoofing | food_handler.go Create | mitigate | created_by set from JWT user_id (middleware-set), not from request body — user cannot claim different identity |
| T-02-04 | Tampering | food_handler.go Update | mitigate | Row-level auth check: nutritionist can only update own items. Super Admin bypass is intentional per D-29 |
| T-02-05 | Tampering | food_dto.go | mitigate | Validator tags enforce ranges (calories ≤9999.99, protein ≤999.99, etc.) per D-32. Name max 200 chars per D-31 |
| T-02-06 | Elevation | food routes | mitigate | RoleGuard("nutritionist", "super_admin") prevents client role access to food endpoints |
| T-02-07 | DoS | List endpoint | mitigate | Limit capped at 100 items per request. Offset-based pagination prevents unbounded queries |
| T-02-08 | Injection | SQL queries | mitigate | All queries via sqlc with parameterized inputs (SEC-03) |
</threat_model>
