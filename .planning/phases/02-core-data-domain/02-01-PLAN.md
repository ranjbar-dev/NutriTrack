**Migration 000004_create_foods.up.sql** — Create the following in order:

1. Enable pg_trgm extension:
   ```sql
   CREATE EXTENSION IF NOT EXISTS pg_trgm;
   ```

2. Create `normalize_persian(text)` SQL function (per D-07) that replaces:
   - `ی` (U+06CC, ARABIC LETTER FARSI YEH) → `ي` (U+064A, ARABIC LETTER YEH)
   - `ک` (U+06A9, ARABIC LETTER KEHEH) → `ك` (U+0643, ARABIC LETTER KAF)
   Using `REPLACE()` nested calls. Function should be `IMMUTABLE` for index usage.

3. Create `food_category` enum (per D-02):
   `'breakfast', 'lunch', 'dinner', 'snack', 'fruit', 'beverage', 'supplement', 'other'`

4. Create `measurement_unit` enum (per D-04):
   `'gram', 'kg', 'tablespoon', 'teaspoon', 'cup', 'piece', 'slice', 'palm', 'matchbox', 'bowl', 'ml', 'liter'`

5. Create `foods` table (per D-01, D-05, D-10):
   ```
   id              UUID PRIMARY KEY DEFAULT gen_random_uuid()
   name            VARCHAR(200) NOT NULL
   name_normalized VARCHAR(200) NOT NULL  -- pre-computed via normalize_persian(LOWER(name))
   description     TEXT
   calories        DECIMAL(8,2) NOT NULL DEFAULT 0
   protein_g       DECIMAL(8,2) NOT NULL DEFAULT 0
   carbs_g         DECIMAL(8,2) NOT NULL DEFAULT 0
   fat_g           DECIMAL(8,2) NOT NULL DEFAULT 0
   fiber_g         DECIMAL(8,2) NOT NULL DEFAULT 0
   sugar_g         DECIMAL(8,2) NOT NULL DEFAULT 0
   sodium_mg       DECIMAL(8,2) NOT NULL DEFAULT 0
   measurement_unit   measurement_unit NOT NULL DEFAULT 'gram'
   measurement_amount DECIMAL(8,2) NOT NULL DEFAULT 100
   is_active       BOOLEAN NOT NULL DEFAULT true
   created_by      UUID NOT NULL REFERENCES users(id)
   created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
   updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
   ```

6. Create GIN trigram index on `name_normalized` for fuzzy search (per D-06):
   ```sql
   CREATE INDEX idx_foods_name_trgm ON foods USING GIN (name_normalized gin_trgm_ops);
   ```

7. Create additional indexes:
   - `CREATE INDEX idx_foods_is_active ON foods (is_active);`
   - `CREATE INDEX idx_foods_created_by ON foods (created_by);`

8. Create `food_categories` junction table (per D-02):
   ```
   food_id   UUID NOT NULL REFERENCES foods(id) ON DELETE CASCADE
   category  food_category NOT NULL
   PRIMARY KEY (food_id, category)
   ```

**Migration 000004_create_foods.down.sql** — Drop in reverse order:
`DROP TABLE IF EXISTS food_categories; DROP TABLE IF EXISTS foods; DROP TYPE IF EXISTS measurement_unit; DROP TYPE IF EXISTS food_category; DROP FUNCTION IF EXISTS normalize_persian; DROP EXTENSION IF EXISTS pg_trgm;`

**Migration 000005_create_medications.up.sql**:

1. Create `medication_form` enum (per D-17, MED-03):
   `'tablet', 'capsule', 'syrup', 'injection', 'drop', 'powder', 'other'`

2. Create `medications` table:
   ```
   id               UUID PRIMARY KEY DEFAULT gen_random_uuid()
   name             VARCHAR(200) NOT NULL
   name_normalized  VARCHAR(200) NOT NULL
   generic_name     VARCHAR(200)
   generic_name_normalized VARCHAR(200)
   form             medication_form NOT NULL DEFAULT 'tablet'
   dosage_unit      VARCHAR(50)
   description      TEXT
   is_active        BOOLEAN NOT NULL DEFAULT true
   created_by       UUID NOT NULL REFERENCES users(id)
   created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW()
   updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW()
   ```

3. Create GIN trigram indexes:
   ```sql
   CREATE INDEX idx_medications_name_trgm ON medications USING GIN (name_normalized gin_trgm_ops);
   CREATE INDEX idx_medications_generic_trgm ON medications USING GIN (generic_name_normalized gin_trgm_ops) WHERE generic_name_normalized IS NOT NULL;
   ```

4. Create additional indexes:
   - `CREATE INDEX idx_medications_is_active ON medications (is_active);`
   - `CREATE INDEX idx_medications_created_by ON medications (created_by);`

**Migration 000005_create_medications.down.sql**:
`DROP TABLE IF EXISTS medications; DROP TYPE IF EXISTS medication_form;`

**docker-compose.dev.yml** — Update the postgres service to use `postgres:16` (Debian-based) instead of `postgres:16-alpine` to ensure `fa_IR.UTF-8` locale is available (per D-09). Add environment variables:
```yaml
POSTGRES_INITDB_ARGS: "--locale=C.UTF-8"
```
Note: Use `C.UTF-8` for default locale (universally available). Persian collation will be handled via ICU collation in PostgreSQL if needed, or via application-level sorting. The critical thing is UTF-8 encoding for correct Persian character storage and pg_trgm byte-level trigram matching. If the executor finds that `fa_IR.UTF-8` is available in the Debian image, use it. Otherwise `C.UTF-8` is sufficient since pg_trgm and normalize_persian handle the search correctly regardless of locale.

**Step 2: Test normalize_persian function**
```sql
SELECT normalize_persian('مرغ کبابی');  -- ک should become ك
SELECT normalize_persian('ماهی');        -- ی should become ي
SELECT normalize_persian('کیک شکلاتی'); -- both ک→ك and ی→ي
```
Expected: characters are normalized.

**Step 3: Insert sample Persian food data**
```sql
INSERT INTO foods (name, name_normalized, calories, protein_g, carbs_g, fat_g, fiber_g, sugar_g, sodium_mg, measurement_unit, measurement_amount, created_by)
VALUES 
  ('مرغ کبابی', LOWER(normalize_persian('مرغ کبابی')), 239, 27.3, 0, 13.6, 0, 0, 82, 'gram', 100, (SELECT id FROM users LIMIT 1)),
  ('برنج سفید', LOWER(normalize_persian('برنج سفید')), 130, 2.7, 28, 0.3, 0.4, 0, 1, 'gram', 100, (SELECT id FROM users LIMIT 1)),
  ('ماهی قزل آلا', LOWER(normalize_persian('ماهی قزل آلا')), 208, 20, 0, 13, 0, 0, 59, 'gram', 100, (SELECT id FROM users LIMIT 1)),
  ('کیک شکلاتی', LOWER(normalize_persian('کیک شکلاتی')), 371, 4.3, 50.3, 14.9, 2.3, 35, 378, 'piece', 1, (SELECT id FROM users LIMIT 1)),
  ('سالاد سزار', LOWER(normalize_persian('سالاد سزار')), 170, 7.5, 9.4, 12.3, 1.5, 2.3, 580, 'bowl', 1, (SELECT id FROM users LIMIT 1));
```

**Step 4: Test ILIKE search with normalization (per D-08)**
```sql
-- Search with ک (KEHEH) — should find 'کیک شکلاتی' stored with normalized ك
SELECT name, name_normalized 
FROM foods 
WHERE name_normalized ILIKE '%' || LOWER(normalize_persian('کیک')) || '%';

-- Search with ی (FARSI YEH) — should find 'ماهی' stored with normalized ي  
SELECT name, name_normalized
FROM foods
WHERE name_normalized ILIKE '%' || LOWER(normalize_persian('ماهی')) || '%';
```

**Step 5: Test pg_trgm similarity scoring**
```sql
-- Fuzzy search — should return results ranked by similarity
SELECT name, similarity(name_normalized, LOWER(normalize_persian('مرق'))) AS score
FROM foods
WHERE name_normalized % LOWER(normalize_persian('مرق'))
   OR name_normalized ILIKE '%' || LOWER(normalize_persian('مرق')) || '%'
ORDER BY score DESC;
```

**Step 6: Test duplicate name check with normalization (per D-33)**
```sql
-- Should detect duplicate regardless of ی/ي variant
SELECT EXISTS(
  SELECT 1 FROM foods 
  WHERE LOWER(normalize_persian(name)) = LOWER(normalize_persian('مرغ كبابي'))
  AND is_active = true
) AS is_duplicate;
```

**Step 7: Clean up test data**
```sql
DELETE FROM foods WHERE name IN ('مرغ کبابی', 'برنج سفید', 'ماهی قزل آلا', 'کیک شکلاتی', 'سالاد سزار');
```

If any step fails, document the issue and investigate. The pg_trgm similarity threshold may need tuning — default is 0.3 which may be too high for short Persian words. Consider `SET pg_trgm.similarity_threshold = 0.1;` for better recall.

Run these queries via `docker compose -f docker-compose.dev.yml exec postgres psql -U nutritrack -d nutritrack` or via a Go test script.
