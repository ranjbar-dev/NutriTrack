## Context

Backups are incomplete until uploads are persistent and restore steps are codified. This plan focuses on making both PostgreSQL and filesystem backups explicit in-repo.

## Objective

Add persistent uploads storage plus repository-owned backup and restore automation for database and file assets.

## Tasks

<task>
  <name>Persist uploads in the production Compose stack</name>
  <read_first>
    - docker-compose.yml
    - backend\internal\config\config.go
    - backend\cmd\api\main.go
  </read_first>
  <action>
    Mount the uploads directory used by the backend to a named volume or explicit bind-backed path in docker-compose.yml, and ensure the configured UPLOADS_DIR matches the mounted path. Do not leave uploads on an ephemeral container filesystem.
  </action>
  <acceptance_criteria>
    - docker-compose.yml mounts UPLOADS_DIR for the api service
    - docker-compose.yml declares an uploads-related volume
    - .env.example contains an UPLOADS_DIR path used by the mount
  </acceptance_criteria>
</task>

<task>
  <name>Add PostgreSQL backup and restore scripts</name>
  <read_first>
    - docker-compose.yml
    - .env.example
  </read_first>
  <action>
    Create PowerShell scripts under docker\backup for pg_dump backup and restore using the existing Postgres container/service names and environment variables. Include timestamped backup filenames, destination directories, and commands that can restore into a target database for launch verification.
  </action>
  <acceptance_criteria>
    - docker\backup\postgres-backup.ps1 exists
    - docker\backup\restore-postgres.ps1 exists
    - postgres-backup.ps1 contains pg_dump
    - restore-postgres.ps1 contains psql or pg_restore
  </acceptance_criteria>
</task>

<task>
  <name>Add uploads backup and restore scripts plus Compose wiring</name>
  <read_first>
    - docker-compose.yml
    - .env.example
  </read_first>
  <action>
    Create uploads-backup.ps1 and restore-uploads.ps1 for archiving and restoring the uploads volume contents. Wire backup runner services or documented one-shot commands into docker-compose.yml so both database and uploads backups can be invoked consistently from the repository.
  </action>
  <acceptance_criteria>
    - docker\backup\uploads-backup.ps1 exists
    - docker\backup\restore-uploads.ps1 exists
    - docker-compose.yml contains backup service or command definitions
  </acceptance_criteria>
</task>

## Verification

- `docker compose config` renders successfully
- Backup/restore scripts exist and reference the actual Compose service names and mount paths

## Success Criteria

- Database and uploads backups are both codified in the repo
- Upload persistence is no longer ephemeral
- Restore steps are explicit enough to execute during launch verification
