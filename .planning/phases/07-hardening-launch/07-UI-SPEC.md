# Phase 7 — UI Design Contract: Hardening & Launch

> Visual and interaction contract for Phase 7 final polish. This phase adds **zero new product features**.
> Every item in this contract is a quality enforcement or gap-fill obligation on existing screens.
> Generated by gsd-ui-researcher, consumed by gsd-planner and gsd-executor.

---

## Phase Scope Declaration

### In scope (UI dimension)
- Natural Persian copy across all three role flows (client, nutritionist, super admin)
- Polished loading, empty, and error states on every screen that currently shows raw strings or blank areas
- PWA install / update banner copy and visual polish (`client.vue` layout)
- Offline mode banner and sync-status strip clarity and accessibility
- Touch-target audit — all interactive elements meet 44 × 44 px minimum on mobile
- Visual stability on 3G startup (no layout shift, no FOUC, Vazirmatn font preloaded)
- RTL layout correctness audit for edge cases (chevrons, icons, input alignment)
- Final launch checklist for manual Android/iOS device QA

### Out of scope (do NOT implement during polish)
- New product screens or flows
- New UI components not already in the codebase
- Desktop breakpoints or responsive widths above 430 px
- Design system migration (shadcn, Radix, etc.)
- New icon libraries

## Spacing Scale

Tailwind v4 default scale used throughout. Phase 7 enforces **no new spacing tokens**; use existing values only.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`p-1`, `gap-1`) | Icon gaps, badge padding, dot indicators |
| sm | 8px (`p-2`, `gap-2`) | Compact element spacing, input inner padding |
| md | 16px (`p-4`, `gap-4`) | Default card padding, page horizontal padding |
| lg | 24px (`p-6`, `gap-6`) | Section padding, modal inner padding |
| xl | 32px (`p-8`) | Major layout gaps (rarely needed at 430 px) |
| 2xl | 48px (`py-12`) | Empty-state vertical centering |
| 3xl | 64px (`pb-16`, `pb-24`) | Bottom padding to clear the fixed bottom nav (80 px) |

**Touch target exception:** All tappable elements must render at minimum 44 × 44 px physical size.
Use `min-h-[44px] min-w-[44px]` where the visual element is smaller (e.g., icon-only close buttons,
status badge toggles, send button in messages).

The existing `pb-20` / `pb-24` bottom-nav clearance pattern is **correct** — do not change it.

## Typography

Vazirmatn is a variable font; weight tokens map to named axes. Phase 7 audits existing usage
and enforces consistency — no new sizes.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px (`text-sm`) | 400 regular | 1.5 | List items, message text, card body, form help text |
| Label | 12px (`text-xs`) | 400 regular | 1.4 | Meta info (timestamps, unit labels, status chips, secondary descriptors) |
| Heading (page) | 20px (`text-xl`) | 700 bold | 1.2 | Page `<h1>` titles |

**Enforcement rules for Phase 7:**
- No bare `font-bold` on `text-xs` elements — use `font-medium` at 12 px maximum.
- All error copy: `text-sm text-red-600` — never raw red text without size.
- All loading placeholder copy: `text-sm text-gray-400` — matches the existing inline loading pattern.
- Empty-state heading: `font-bold text-gray-800` at `text-base` (16 px).
- Empty-state body: `text-sm text-gray-500`.

### Loading States

All loading states must use the **skeleton pulse** pattern already in `client/plan.vue` —
`animate-pulse rounded-2xl bg-white shadow-sm h-{N}` — never bare spinner-only for full-page loads.
`LoadingSpinner.vue` is reserved for inline / button-level loading only.

| Screen | Loading copy / pattern |
|--------|----------------------|
| Any full-page initial load | 3–4 skeleton cards, no copy |
| Inline async (send, save) | Button disabled + `opacity-50`, no spinner text |
| Message list loading | `در حال بارگذاری...` (`text-sm text-gray-400 text-center`) |
| Client list loading | `در حال بارگذاری...` or skeleton rows |
| Client profile loading | `در حال بارگذاری...` centered in `py-8` |
| Nutritionist tracking tabs | Skeleton row × 3 |

**Phase 7 audit rule:** Replace all bare `در حال بارگذاری...` text-only loading states in full-page
contexts with skeleton pulse cards. Text-only loading is acceptable only inside a chat scroll area.

### Error States

| Scenario | Copy | Pattern |
|----------|------|---------|
| API fetch failure (page-level) | خطا در بارگذاری اطلاعات. دوباره تلاش کنید. | Red text block + تلاش مجدد button |
| Form save failure | خطا در ذخیره‌سازی — already correct in `[clientId]/index.vue` | `text-red-500 text-xs` inline below form |
| Message send failure | پیام ارسال نشد. دوباره تلاش کنید. | `text-red-500 text-sm` above input bar |
| Sync item failure | `N خطا` + تلاش مجدد link — already correct in `ClientSyncStatus.vue` | keep as-is |
| File too large | فایل انتخابی بزرگ‌تر از حد مجاز است. | inline `text-red-500 text-xs` |
| File type rejected | فرمت فایل پشتیبانی نمی‌شود. | inline `text-red-500 text-xs` |
| Network timeout | اتصال برقرار نشد. وضعیت اینترنت را بررسی کنید. | toast or inline depending on context |
| Session expired / 401 | نشست شما منقضی شده است. لطفاً دوباره وارد شوید. | full redirect to login (existing behavior) |
| Permission denied / 403 | دسترسی مجاز نیست. | `unauthorized.vue` page (existing) |

**Error rule:** No raw API error objects, English stack traces, or JSON bodies must ever reach the user.
All `catch` blocks must display a human-readable Persian fallback string if the server response has no `error` field.

## PWA Launch & Visual Stability Contract

### Startup Performance (3G baseline, after first visit)

| Metric | Target | Enforcement method |
|--------|--------|-------------------|
| PWA initial load (3G) | < 3 seconds to interactive | Chrome DevTools 3G throttle + Lighthouse |
| First Contentful Paint | < 1.5 s (3G) | Lighthouse audit |
| Layout Shift (CLS) | < 0.1 | No unstyled font flash, no skeleton-to-content jump |
| Vazirmatn font | Must not cause FOUT | `font-display: swap` verified in `Vazirmatn-Variable-font-face.css` |
| JS bundle initial chunk | < 150 KB gzipped | `nuxt build` + `nuxt analyze` output |
| App manifest icons | All 3 sizes present (192, 384, 512) | manifest audit |
| Standalone display | Must not show browser chrome on Android/iOS | `display: standalone` in manifest |
| Start URL | `/client/plan` for client role | manifest `start_url` — already correct |

### Visual Stability Rules

- **No unstyled content flash:** `bg-gray-50` body background must paint before any content renders.
  Body background is set in `main.css` and in PWA manifest `background_color: #f9fafb` — these must match.
- **Skeleton first:** All pages that call `onMounted` → async fetch must show skeleton frames before
  content renders. The `v-if="pageLoading"` → skeleton pattern in `client/plan.vue` is the **canonical model**.
- **Bottom nav must not reflow:** The fixed bottom nav (`pb-20` / `pb-24` body padding) must be present
  from first paint, not added after JS hydration.
- **Sticky headers must not jump:** Pages with `sticky top-0` headers must maintain `bg-white` or
  `bg-gray-50` backgrounds — no transparent sticky headers that reveal scroll content behind them.

### iOS PWA Specific

- Status bar safe area: verify `env(safe-area-inset-*)` is respected on notched iPhones (no content
  hidden behind status bar or home indicator).
- Viewport `maximum-scale=1` is already set — do not change.
- Standalone mode on iOS Safari: test that back navigation works without browser chrome.

### RTL Correctness Audit

| Element | Expected behaviour | Common failure |
|---------|--------------------|---------------|
| Chevron / arrow icons | Point right `›` for RTL "go to next" | Wrong direction — audit `<span>‹</span>` in `client/profile.vue` |
| Back navigation arrows | `←` for "go back" in RTL is **correct** (points toward past = left in LTR convention, but in RTL "back" is still leftward visually) | Confirm `←` usage in nutritionist profile is intentional |
| Input text alignment | RTL auto-align (`text-right` or `dir=auto`) for textarea/input | `messages.vue` textarea — verify alignment |
| Message bubbles | Own messages: start-aligned (right side in RTL) | Current: `justify-start` for own — verify RTL produces right-side bubble |
| `start-` / `end-` utilities | Use `start-4 end-4` not `left-4 right-4` for RTL-safe positioning | Both PWA banners already use `start-4 end-4` ✅ |
| `me-` / `ms-` margins | Use `me-auto` not `mr-auto` for RTL-safe auto margins | `ClientSyncStatus` uses `me-auto` ✅ |

**Rule for Phase 7:** Any use of `left-*`, `right-*`, `ml-*`, `mr-*`, `pl-*`, `pr-*` in components
must be replaced with logical equivalents (`start-*`, `end-*`, `ms-*`, `me-*`, `ps-*`, `pe-*`)
unless the layout intent is genuinely direction-independent (e.g., a centred element).

### Scroll Behaviour

- All scrollable lists: `overflow-y-auto` — no custom scroll libraries.
- Chat message list: scroll-to-bottom on new message — verify this is implemented in `messages.vue`.
- Day tab bar: horizontal scroll on overflow — verify `overflow-x-auto` with no visible scrollbar
  (`scrollbar-hide` or native `-webkit-overflow-scrolling: touch`).
- No bounce-scroll issues on iOS: `overscroll-behavior-y: contain` where needed.
