    2. Create `backend/internal/service/auth_service.go`:
       ```go
       type AuthService struct {
           userRepo  repository.UserRepository
           otpRepo   repository.OTPRepository
           tokenRepo repository.TokenRepository
           smsSender sms.Sender
           jwtSecret []byte
           logger    zerolog.Logger
       }
       ```

       Methods:

       **LoginWithPassword(ctx, email, password string) (*model.TokenPair, *dto.UserResponse, error):**
       - Looks up user by email
       - Compares password with bcrypt (cost 12 per AUTH-10)
       - Returns SAME error for "user not found" AND "wrong password" (prevent enumeration per RESEARCH.md anti-patterns): `"ایمیل یا رمز عبور اشتباه است"`
       - Creates token pair and refresh token DB record
       - Returns tokens + user response

       **RequestOTP(ctx, mobile string) error:**
       - Normalizes phone to 10-digit canonical format (strip leading 0, +98, 0098)
       - Generates random 6-digit OTP code (crypto/rand, not math/rand)
       - Hashes OTP with SHA-256 before storing (per RESEARCH.md — never store plaintext)
       - Creates OTP record with 2-minute expiry, max 3 attempts (AUTH-06)
       - Sends via SMS sender interface
       - Returns SAME response whether user exists or not (prevent enumeration)

       **VerifyOTP(ctx, mobile, code string) (*model.TokenPair, *dto.UserResponse, error):**
       - Normalizes phone
       - Retrieves active OTP for mobile
       - Checks attempts < max_attempts (AUTH-06: max 3)
       - Increments attempt counter
       - Compares SHA-256 hash of submitted code with stored code_hash
       - If valid: marks OTP verified, looks up user, creates token pair
       - Returns SAME error for all failure modes (no code, wrong code, expired, max attempts)

       **RefreshTokens(ctx, refreshTokenStr string) (*model.TokenPair, error):**
       - Hashes received refresh token with SHA-256
       - Looks up in DB by hash
       - Checks not revoked, not expired
       - Revokes old token
       - Creates new token pair + new refresh token record with same family_id (rotation)
       - If token already revoked (replay detection): revoke entire family via family_id (theft detection per RESEARCH.md)

       **Logout(ctx, refreshTokenStr string) error:**
       - Revokes refresh token

       - Call `authService.LoginWithPassword()`
       - On success: set httpOnly cookies via `setAuthCookies()` and return 200 + user JSON
       - On failure: return 401 with Persian error

       **POST /api/auth/otp/request** (AUTH-05):
       - Bind JSON to `dto.OTPRequestDTO` (validates Iranian mobile format — SEC-02)
       - Call `authService.RequestOTP()`
       - Always return 200 with `{"message": "کد تایید ارسال شد"}` (prevent enumeration)

       **POST /api/auth/otp/verify** (AUTH-05, AUTH-06):
       - Bind JSON to `dto.OTPVerifyDTO`
       - Call `authService.VerifyOTP()`
       - On success: set httpOnly cookies, return 200 + user
       - On failure: return 401

       **POST /api/auth/refresh** (AUTH-08):
       - Read refresh_token from cookie
       - Call `authService.RefreshTokens()`
       - On success: set new cookies, return 200
       - On failure: clear cookies, return 401

       **POST /api/auth/logout:**
       - Read refresh_token from cookie
       - Call `authService.Logout()`
       - Clear all auth cookies
       - Return 200

       **GET /api/auth/me** (session persistence on page refresh):
       - This endpoint is auth-protected (requires valid access_token cookie)
       - Reads user_id from Gin context (set by Auth middleware JWT parsing)
       - Calls `userRepo.GetByID(ctx, userID)` to fetch current user from DB
       - Returns 200 with `{ user: { id, role, full_name, email, mobile } }` (same shape as login response)
       - If user not found or token invalid: returns 401
       - Purpose: Frontend `checkAuth()` calls this on hard refresh to restore session state without re-login

       Cookie helper functions per RESEARCH.md Pattern 2:
       ```go
       func setAuthCookies(c *gin.Context, tokens *model.TokenPair) {
           c.SetCookie("access_token", tokens.AccessToken, 900, "/api", "", true, true)
           c.SetCookie("refresh_token", tokens.RefreshToken, 2592000, "/api/auth/refresh", "", true, true)
       }
       func clearAuthCookies(c *gin.Context) {
           c.SetCookie("access_token", "", -1, "/api", "", true, true)
           c.SetCookie("refresh_token", "", -1, "/api/auth/refresh", "", true, true)
       }
       ```
       **Cookie details per D-01:**
       - access_token: path=/api, maxAge=900 (15min), secure=true, httpOnly=true
       - refresh_token: path=/api/auth/refresh, maxAge=2592000 (30d), secure=true, httpOnly=true

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → Public API | Unauthenticated requests (login, OTP, health) |
| Client → Protected API | JWT-authenticated requests (admin, nutritionist, client routes) |
| API → Database | Trusted Docker network, parameterized queries |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | Login endpoint | mitigate | Same error for invalid email AND wrong password (anti-enumeration) |
| T-04-02 | Spoofing | OTP endpoint | mitigate | Same response for existing/non-existing phone (anti-enumeration) |
| T-04-03 | Elevation of Privilege | OTP brute force | mitigate | 3 attempts max per code (AUTH-06) + rate limiter 3 req/10min (AUTH-07) |
| T-04-04 | Elevation of Privilege | Client self-registration | mitigate | No public registration endpoint; clients created only by nutritionists (AUTH-12) |
| T-04-05 | Tampering | Refresh token replay | mitigate | Stateful rotation with family_id; replay revokes entire family |
| T-04-06 | Tampering | OTP storage | mitigate | OTP hashed with SHA-256 before storage; crypto/rand for generation |
| T-04-07 | Information Disclosure | Row-level access | mitigate | Repository WHERE clauses include nutritionist_id; return 404 not 403 (AUTH-11) |
| T-04-08 | Tampering | Input validation | mitigate | go-playground/validator struct tags on all DTOs (SEC-02) |
