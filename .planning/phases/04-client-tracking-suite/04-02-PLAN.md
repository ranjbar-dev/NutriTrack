**local_id idempotent pattern** (for water_logs, exercise_logs, medication_logs — DO NOTHING tables):
```go
func (r *trackingRepository) LogWater(ctx context.Context, clientID uuid.UUID, req dto.LogWaterRequest) (*dto.WaterLogResponse, error) {
    localID := uuid.MustParse(req.LocalID)
    params := sqlc.CreateWaterLogParams{
        ClientID: pgtype.UUID{Bytes: clientID, Valid: true},
        LocalID:  pgtype.UUID{Bytes: localID, Valid: true},
        // ... date, amount_ml, logged_time
    }
    row, err := r.q.CreateWaterLog(ctx, params)
    if errors.Is(err, pgx.ErrNoRows) {
        // local_id already exists — fetch and return existing record
        existing, err := r.q.GetWaterLogByLocalID(ctx, sqlc.GetWaterLogByLocalIDParams{
            LocalID:  pgtype.UUID{Bytes: localID, Valid: true},
            ClientID: pgtype.UUID{Bytes: clientID, Valid: true},
        })
        if err != nil {
            return nil, err
        }
        return toWaterLogResponse(existing), nil
    }
    if err != nil {
        return nil, err
    }
    return toWaterLogResponse(row), nil
}
```

Apply same pattern to `LogExercise` and `LogMedication`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Handler → Repository | client_id always sourced from JWT (c.GetString("user_id")), never from request body |
| Repository → Database | Nutritionist ownership enforced by SQL JOIN, not by application-level filtering |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Elevation of Privilege | ListXxxForNutritionist | mitigate | SQL JOIN `users.nutritionist_id = $nutritionist_id` on every nutritionist read query; zero rows returned if ownership fails |
| T-04-02-02 | Tampering | local_id replay | mitigate | `ON CONFLICT (local_id) DO NOTHING` + two-step SELECT returns same record; no duplicate rows created |
| T-04-02-03 | Elevation of Privilege | GetLabResultForNutritionist | mitigate | `GetLabResultForNutritionist` query requires both `lab_id` and `nutritionist_id`; returns 404 if mismatch |
</threat_model>
