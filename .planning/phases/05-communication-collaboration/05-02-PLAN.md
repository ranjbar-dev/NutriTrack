## Context

This plan implements the messaging backend layer: repository (sqlc-backed), service (business logic + file upload security), handler (HTTP endpoints), and route wiring.

## Tasks

### 2. CommunicationService

**File**: `backend/internal/service/communication_service.go`

Error sentinels:
- `ErrCommNotFound = errors.New("رکورد یافت نشد")`
- `ErrCommUnauthorized = errors.New("دسترسی غیرمجاز")`
- `ErrMsgAttachmentTooLarge = errors.New("حجم فایل بیش از حد مجاز است")`
- `ErrMsgAttachmentInvalidType = errors.New("فرمت فایل مجاز نیست — فقط JPG، PNG و PDF")`

Service depends on: `CommunicationRepository`, `UserRepository` (to verify ownership), `uploadsDir`, `logger`.

Key logic:
- `SendMessage(ctx, senderID uuid.UUID, req dto.SendMessageRequest, fileReader io.Reader, fileSize int64, filename string, contentType string)` — validates content or file present, validates file type (magic bytes via mimetype library), saves file to `uploads/messages/{clientID}/{uuid}.{ext}`, calls repo
- `GetMessages(ctx, requestorID uuid.UUID, partnerID uuid.UUID, limit, offset int)` — verifies sender/receiver are in a valid nutritionist-client pair using userRepo
- `GetNewMessages(ctx, requestorID, partnerID uuid.UUID, since time.Time)` — same ownership check
- `MarkRead(ctx, receiverID, senderID uuid.UUID)` — calls repo
- `GetUnreadCount(ctx, userID uuid.UUID)` — calls repo
- `DownloadAttachment(ctx, requestorID, messageID uuid.UUID)` — fetches message, verifies requestor is sender or receiver, returns file path

Ownership check helper: query userRepo to verify that one user is a client and the other is their assigned nutritionist.

### 3. CommunicationHandler

**File**: `backend/internal/handler/communication_handler.go`

```go
type CommunicationHandler struct {
    svc        *service.CommunicationService
    uploadsDir string
}
```

Methods:
- `SendMessage(c *gin.Context)` — multipart or JSON; if has file: ParseMultipartForm(10<<20), extract file; call svc.SendMessage
- `ListMessages(c *gin.Context)` — GET /api/messages/:partnerId?limit=50&offset=0
- `PollNewMessages(c *gin.Context)` — GET /api/messages/:partnerId/new?since=2006-01-02T15:04:05Z
- `MarkRead(c *gin.Context)` — PATCH /api/messages/:partnerId/read
- `GetUnreadCount(c *gin.Context)` — GET /api/messages/unread-count
- `DownloadAttachment(c *gin.Context)` — GET /api/messages/:messageId/attachment

Error handling via `handleCommError(c, err, fallback)`.

### 4. Wire routes in main.go

Both nutritionist and client share messaging routes (both roles use the same endpoints):

```go
commRepo := repository.NewCommunicationRepository(pool)
commService := service.NewCommunicationService(commRepo, userRepo, cfg.UploadsDir, logger)
commHandler := handler.NewCommunicationHandler(commService, cfg.UploadsDir)

// Messaging — both client and nutritionist roles
msg := r.Group("/api/messages")
msg.Use(middleware.Auth(jwtSecret), middleware.RoleGuard("client", "nutritionist"))
{
    msg.GET("/unread-count", commHandler.GetUnreadCount)
    msg.POST("", commHandler.SendMessage)
    msg.GET("/:partnerId", commHandler.ListMessages)
    msg.GET("/:partnerId/new", commHandler.PollNewMessages)
    msg.PATCH("/:partnerId/read", commHandler.MarkRead)
    msg.GET("/:messageId/attachment", commHandler.DownloadAttachment)
}
```
