## Context

This plan wires the food-request HTTP endpoints. The repository and service methods are already defined in communication_repo.go and communication_service.go from plan 05-02. Here we add the handler methods and route entries.

## Tasks

### 1. Add food-request handler methods to CommunicationHandler

**File**: `backend/internal/handler/communication_handler.go` (extend existing file)

Methods to add:
- `ClientCreateFoodRequest(c *gin.Context)` — POST /api/client/food-requests; binds FoodRequestCreateRequest; calls svc.CreateFoodRequest
- `ClientListFoodRequests(c *gin.Context)` — GET /api/client/food-requests; calls svc.ListFoodRequestsByClient
- `NutriListFoodRequests(c *gin.Context)` — GET /api/nutritionist/food-requests; calls svc.ListPendingFoodRequestsForNutritionist
- `NutriApproveFoodRequest(c *gin.Context)` — PATCH /api/nutritionist/food-requests/:id/approve; verifies the request belongs to a client of this nutritionist; calls svc.ApproveFoodRequest
- `NutriRejectFoodRequest(c *gin.Context)` — PATCH /api/nutritionist/food-requests/:id/reject; binds optional FoodRequestRejectRequest; calls svc.RejectFoodRequest

### 2. Wire routes in main.go

Add to client group:
```go
client.POST("/food-requests", commHandler.ClientCreateFoodRequest)
client.GET("/food-requests", commHandler.ClientListFoodRequests)
```

Add to nutritionist group:
```go
nutri.GET("/food-requests", commHandler.NutriListFoodRequests)
nutri.PATCH("/food-requests/:id/approve", commHandler.NutriApproveFoodRequest)
nutri.PATCH("/food-requests/:id/reject", commHandler.NutriRejectFoodRequest)
```
