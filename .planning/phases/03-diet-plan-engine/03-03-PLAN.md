**Service methods** — implement all the following:

1. `CreatePlan(ctx, nutritionistID uuid.UUID, req dto.CreateDietPlanRequest) (*dto.DietPlanSummaryResponse, error)`:
   - Parse clientID from req.ClientID
   - Parse dates from strings (req.StartDate, req.EndDate → time.Time via time.Parse("2006-01-02", ...))
   - Validate end_date >= start_date (return ErrPlanNotDraft if reversed — or a new ErrInvalidDateRange)
   - Call planRepo.CreatePlan with sqlc.CreateDietPlanParams
   - Return DietPlanSummaryResponse

2. `GetPlanAggregate(ctx, planID, nutritionistID uuid.UUID) (*dto.DietPlanResponse, error)`:
   - Call planRepo.GetFullPlanAggregate(ctx, planID)
   - Verify nutritionistID matches response.NutritionistID (or let repo handle via GetPlanByID first)
   - Return result or ErrPlanNotFound / ErrPlanUnauthorized

3. `ListClientPlans(ctx, clientID, nutritionistID uuid.UUID, page, limit int) (*dto.DietPlanListResponse, error)`:
   - Default limit=20, max=100; compute offset=(page-1)*limit
   - Call planRepo.ListClientPlans + CountClientPlans
   - Return DietPlanListResponse with HasMore

4. `UpdatePlanHeader(ctx, planID, nutritionistID uuid.UUID, req dto.UpdateDietPlanRequest) (*dto.DietPlanSummaryResponse, error)`:
   - GetPlanByID; check status == draft (else ErrPlanNotDraft)
   - Call planRepo.UpdatePlanHeader
   - Return updated summary

5. `ActivatePlan(ctx, planID, nutritionistID uuid.UUID) error` — CRITICAL method:
   - GetPlanByID; if not found → ErrPlanNotFound
   - If already active → ErrPlanAlreadyActive
   - Call validatePlanComplete(ctx, planID) → if error → return ErrPlanIncomplete
   - Call planRepo.ArchivePreviousActivePlan(ctx, clientID, planID)
   - Call planRepo.ActivatePlan(ctx, planID, nutritionistID)
   - Log success: s.logger.Info()...
   - If planRepo.ActivatePlan returns unique constraint violation (duplicate key value): translate to ErrPlanAlreadyActive (race condition backstop)

6. `validatePlanComplete(ctx context.Context, planID uuid.UUID) error` — private method:
   - Call planRepo.GetFullPlanAggregate(ctx, planID)
   - Check: len(plan.Days) == 0 → return ErrPlanIncomplete
   - For each day: len(day.Meals) == 0 → return ErrPlanIncomplete
   - For each meal: len(meal.Options) == 0 → return ErrPlanIncomplete
   - For each option: len(option.Items) == 0 → return ErrPlanIncomplete
   - Return nil if all checks pass

7. `DeletePlan(ctx, planID, nutritionistID uuid.UUID) error`:
   - GetPlanByID; if status != draft → ErrPlanNotDraft
   - Call planRepo.DeletePlan

8. `GetActivePlanForClient(ctx, clientID uuid.UUID) (*dto.DietPlanResponse, error)`:
   - Call planRepo.GetActivePlanForClient
   - If pgx.ErrNoRows → return nil, pgx.ErrNoRows (handler translates to 404)
   - Return response

9-onwards: Sub-resource service methods for days, meals, options, items, exercises, medications. Each follows the pattern:
   - Parse IDs, validate parent ownership (use GetPlanByID first for day/meal methods to confirm nutritionist_id chain)
   - Call repo method
   - Return response DTO
   - Map pgx.ErrNoRows → ErrXxxNotFound

   Implement: AddDay, UpdateDay, DeleteDay, AddMeal, UpdateMeal, DeleteMeal, ReorderMeal, AddOption, DeleteOption, AddItem, UpdateItem, DeleteItem, AddExercise, UpdateExercise, DeleteExercise, AddMedication, UpdateMedication, DeleteMedication

For date/time parsing: use `time.Parse("2006-01-02", dateStr)` for DATE fields; use `time.Parse("15:04", timeStr)` for TIME fields.
For pgtype conversion: use `pgtype.Date{Time: t, Valid: true}`, `pgtype.Time{Microseconds: int64(t.Hour()*3600+t.Minute()*60)*1e6, Valid: true}`.
For optional strings: use `optionalText()` (already in package from food_service.go — same package, do not re-declare).
For JSONB times field: encode []string as JSON bytes via `json.Marshal(req.Times)` → `pgtype.JSONB{Bytes: bytes, Valid: true}`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → Gin handler | Untrusted input: all URL params, query params, JSON body |
| Handler → Service | Parsed and validated inputs; trust established |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-A | Elevation of Privilege | /api/diet-plans routes — unauthorized role access | mitigate | RoleGuard("nutritionist","super_admin") middleware on all diet-plan routes; RoleGuard("client") on /me/active-plan — enforced in main.go route group |
| T-03-03-B | Elevation of Privilege | Cross-client plan access via crafted plan ID | mitigate | Repository GetPlanByID includes `AND nutritionist_id=$2` — nutritionist cannot access another nutritionist's plans even if they guess the UUID |
| T-03-03-C | Tampering | Race condition: concurrent plan activation | mitigate | DB partial unique index (Plan 01) is the backstop — second activation returns pgx unique constraint error → translated to ErrPlanAlreadyActive → 409 |
| T-03-03-D | DoS | Activation with incomplete plan creates orphan active plans | mitigate | validatePlanComplete() called BEFORE ArchivePreviousActivePlan — no archival happens if plan is incomplete |
| T-03-03-E | Spoofing | Client uses nutritionist token to build plans for others | mitigate | JWT user_id extracted by auth middleware; every repo call passes nutritionistID from JWT — URL clientId is validated against this |
| T-03-03-F | Information Disclosure | 500 error leaks stack trace | mitigate | Default error handler returns generic "خطا در پردازش درخواست" — no internal details exposed |
