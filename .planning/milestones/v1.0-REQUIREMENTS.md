# Requirements: NutriTrack

**Defined:** 2025-07-18
**Core Value:** Digitalize the nutritionist–client workflow in Iran, replacing WhatsApp + Excel + paper with a structured, offline-capable PWA

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Authentication & Authorization

- [x] **AUTH-01**: Super Admin can log in with email and password
- [x] **AUTH-02**: Super Admin account is seeded via backend migration or CLI command (no self-registration)
- [x] **AUTH-03**: Nutritionist can log in with email and password
- [x] **AUTH-04**: Nutritionist accounts are created exclusively by Super Admin (no self-registration)
- [x] **AUTH-05**: Client receives OTP via SMS (Kavenegar) to registered mobile number for login
- [x] **AUTH-06**: OTP is 6 digits, valid for 2 minutes, max 3 attempts per code
- [x] **AUTH-07**: OTP rate limit: max 3 requests per phone per 10 minutes
- [x] **AUTH-08**: JWT access token (15 min) + refresh token (30 days) issued on successful auth
- [x] **AUTH-09**: JWT refresh handles concurrent requests without mass logout (refresh queue pattern)
- [x] **AUTH-10**: Passwords hashed with bcrypt (cost factor 12)
- [x] **AUTH-11**: Row-level authorization: nutritionist can only access own clients' data (repository-level enforcement)
- [x] **AUTH-12**: Client cannot self-register — only nutritionist can register clients

### Food Database

- [x] **FOOD-01**: Shared platform-wide food database accessible to Super Admin and all Nutritionists
- [x] **FOOD-02**: Food item CRUD with fields: name, categories, calories, protein, carbs, fat, fiber, sugar, sodium, measurement_unit, measurement_amount, description
- [x] **FOOD-03**: Food categories (many-to-many): breakfast, lunch, dinner, snack, fruit, beverage, supplement, other
- [x] **FOOD-04**: 12 measurement units supported (gram, kg, tablespoon, teaspoon, cup, piece, slice, palm, matchbox, bowl, ml, liter)
- [x] **FOOD-05**: Persian full-text search on food name using pg_trgm with correct UTF-8 locale
- [x] **FOOD-06**: Persian character normalization (ی/ي, ک/ك) at storage and query boundaries
- [x] **FOOD-07**: Filter by category, active/inactive status
- [x] **FOOD-08**: Pagination with 20 items per page
- [x] **FOOD-09**: Soft delete via is_active flag
- [x] **FOOD-10**: Audit trail: created_by tracks who added each item

### Medication Database

- [x] **MED-01**: Shared platform-wide medication database accessible to Super Admin and all Nutritionists
- [x] **MED-02**: Medication CRUD with fields: name, generic_name, form, dosage_unit, description
- [x] **MED-03**: Medication forms: tablet, capsule, syrup, injection, drop, powder, other
- [x] **MED-04**: Search on medication name (Persian-aware)
- [x] **MED-05**: Soft delete via is_active flag

### Diet Plan Management

- [x] **DIET-01**: Nutritionist can create a diet plan for own client with: start_date, end_date, notes, daily_water_target_ml, status
- [x] **DIET-02**: Only one active diet plan per client at any time; new plan auto-archives previous
- [x] **DIET-03**: Diet plan has nested structure: Plan → Days → Meals → Options → Items
- [x] **DIET-04**: Plan days with day_number supporting unique-per-date and repeating patterns
- [x] **DIET-05**: Meals with title, scheduled_time, display_order
- [x] **DIET-06**: Meal options (client picks one per meal) with option_number
- [x] **DIET-07**: Meal option items link to food database with quantity, measurement_unit, notes
- [x] **DIET-08**: Real-time computed nutritional totals (calories, protein, carbs, fat, fiber) per option, meal, and day
- [x] **DIET-09**: Exercise recommendations per plan day: exercise_name, duration_minutes, description, calories_burn_estimate
- [x] **DIET-10**: Prescribed medications per diet plan: medication, dosage, frequency, times (JSONB), instructions, date range
- [x] **DIET-11**: Archived plans remain viewable for history (both nutritionist and client)
- [x] **DIET-12**: Diet plan aggregate loaded in ≤5 queries using batch loading (pgx SendBatch) — no N+1

### Client Tracking

- [x] **TRACK-01**: Client can log food intake per meal: select option eaten or mark as skipped (optional)
- [x] **TRACK-02**: Client can log water intake: amount_ml, optional time, multiple entries per day
- [x] **TRACK-03**: Water intake shows daily total vs target (if set) with visual progress indicator
- [x] **TRACK-04**: Client can log sleep: sleep_time, wake_time, quality (good/fair/poor), one entry per date
- [x] **TRACK-05**: Sleep duration computed from sleep_time and wake_time
- [x] **TRACK-06**: Client can log exercise: exercise_name, duration_minutes, optional calories_burned, multiple per day
- [x] **TRACK-07**: Client can log medication intake: prescribed or self-reported, dosage, taken_at time
- [x] **TRACK-08**: Client sees prescribed medications with scheduled times, taps to mark as taken
- [x] **TRACK-09**: Client or nutritionist can record body measurements: weight, waist, hip, abdomen, thigh, chest, wrist
- [x] **TRACK-10**: Body measurement history viewable as list and chart (weight over time, measurements over time)
- [x] **TRACK-11**: One body measurement record per date per field (last write wins or update existing)
- [x] **TRACK-12**: All tracking entries have local_id (UUID) for offline sync deduplication
- [x] **TRACK-13**: Nutritionist can view all client tracking data: food logs, weight, measurements, exercise, sleep, water, medication

### Lab Results

- [x] **LAB-01**: Client can upload lab results with: title, type (blood_test, urine_test, thyroid, hormone, allergy, other), date, file or link
- [x] **LAB-02**: At least one of file or link must be provided
- [x] **LAB-03**: Accepted formats: PDF, JPG, PNG; max 10 MB
- [x] **LAB-04**: Nutritionist can view and download all client lab results
- [x] **LAB-05**: Files stored on Hetzner server filesystem

### Messaging

- [x] **MSG-01**: Chat-style messaging between client and assigned nutritionist
- [x] **MSG-02**: Client can only message their assigned nutritionist; nutritionist messages own clients
- [x] **MSG-03**: Text messages with optional attachments (images: JPG/PNG max 5 MB, files: PDF max 10 MB)
- [x] **MSG-04**: Polling-based delivery (every 10 seconds when chat is open)
- [x] **MSG-05**: Unread message count shown as badge
- [x] **MSG-06**: Messages ordered chronologically, no editing or deletion
- [x] **MSG-07**: Read receipts (read_at timestamp)

### Food Requests

- [x] **FREQ-01**: Client can submit food addition request with name and optional description
- [x] **FREQ-02**: Request goes to client's assigned nutritionist
- [x] **FREQ-03**: Nutritionist can approve (creates food item in shared DB) or reject (with optional reason)
- [x] **FREQ-04**: Client receives notification of approval/rejection

### Client Management

- [x] **CLNT-01**: Nutritionist can register client: full_name, mobile (unique Iranian format), date_of_birth, height_cm, gender, notes
- [x] **CLNT-02**: Client list view: name, mobile, status, current plan status, last activity, searchable by name/mobile
- [x] **CLNT-03**: Client list filterable by active/inactive, sortable by name or last activity
- [x] **CLNT-04**: Client profile view with personal info, current plan summary, and history tabs (weight, food, exercise, water, sleep, medication, lab results, archived plans)
- [x] **CLNT-05**: Quick actions from client profile: new diet plan, send message, deactivate client
- [x] **CLNT-06**: Nutritionist can activate/deactivate clients
- [x] **CLNT-07**: Height and date of birth editable only by nutritionist

### Super Admin Panel

- [x] **ADMIN-01**: List all nutritionists: name, email, status, client count, created date
- [x] **ADMIN-02**: Create new nutritionist: name, email, password
- [x] **ADMIN-03**: Activate/deactivate nutritionist accounts
- [x] **ADMIN-04**: View nutritionist's client list (read-only)
- [x] **ADMIN-05**: Full CRUD on food items including ability to edit/delete items created by others
- [x] **ADMIN-06**: Full CRUD on medications
- [x] **ADMIN-07**: View audit log of who created/modified food and medication items
- [x] **ADMIN-08**: Platform statistics: total nutritionists, clients (active/inactive), food items, active diet plans

### Offline & Sync

- [x] **OFFL-01**: Service Worker caches static assets and API responses for client role only
- [x] **OFFL-02**: Active diet plan fully viewable offline
- [x] **OFFL-03**: All tracking (food, water, exercise, sleep, medication, body measurements) works offline with queue
- [x] **OFFL-04**: Queued messages sendable offline
- [x] **OFFL-05**: IndexedDB via Dexie.js stores: active plan, pending logs, cached messages, queued outgoing messages
- [x] **OFFL-06**: Sync manager pushes queued entries on reconnect with last-write-wins conflict resolution
- [x] **OFFL-07**: Each queued entry has local_id (UUID) + synced_at; server deduplicates via ON CONFLICT (local_id) DO NOTHING
- [x] **OFFL-08**: Failed sync retries with exponential backoff (max 3 retries, then flag for manual retry)
- [x] **OFFL-09**: Background Sync API where supported, fallback to polling on app open
- [x] **OFFL-10**: Diet plan cached on first load, refreshed on app open if online
- [x] **OFFL-11**: Cached last 50 messages per conversation, fetch new on open
- [x] **OFFL-12**: Handle iOS PWA storage eviction gracefully (re-fetch on data loss, show pending count)

### Push Notifications

- [x] **NOTIF-01**: Web Push notifications via VAPID keys using webpush-go
- [x] **NOTIF-02**: Client subscribes to push on first login (permission prompt)
- [x] **NOTIF-03**: Notification triggers: new message, new diet plan assigned, food request result
- [x] **NOTIF-04**: Meal time reminders based on diet plan scheduled times
- [x] **NOTIF-05**: Medication reminders based on prescribed medication times
- [x] **NOTIF-06**: Water intake reminders
- [x] **NOTIF-07**: Client can enable/disable each reminder type in notification preferences
- [x] **NOTIF-08**: Notification payload includes: title, body, action URL, icon

### UI/UX & PWA

- [x] **UI-01**: Persian-only RTL layout using Tailwind CSS v4 logical properties (ms-, me-, ps-, pe-, text-start, text-end)
- [x] **UI-02**: Mobile-only viewport design (no desktop optimization)
- [x] **UI-03**: Vazirmatn font for all Persian text
- [x] **UI-04**: Shamsi/Jalali calendar for all date displays using jalaali-js
- [x] **UI-05**: Persian numeral display throughout the app
- [x] **UI-06**: PWA manifest with install prompt
- [x] **UI-07**: Service worker with registerType: autoUpdate for stale cache prevention
- [x] **UI-08**: Initial load < 3 seconds on 3G

### Infrastructure & Performance

- [x] **INFRA-01**: Docker + Docker Compose deployment on Hetzner
- [x] **INFRA-02**: Traefik reverse proxy with HTTPS (Let's Encrypt)
- [x] **INFRA-03**: GitLab CI/CD pipeline for automated testing and deployment
- [x] **INFRA-04**: Structured JSON logging to stdout, collected by Loki
- [x] **INFRA-05**: Grafana dashboards for monitoring
- [x] **INFRA-06**: Health check endpoint
- [x] **INFRA-07**: Daily automated PostgreSQL backups
- [x] **INFRA-08**: Weekly file storage backups
- [x] **INFRA-09**: API response time < 200ms for standard CRUD
- [x] **INFRA-10**: Diet plan load time < 500ms
- [x] **INFRA-11**: Support 50 nutritionists, 10,000 clients, ~500 concurrent users

### Security

- [x] **SEC-01**: All traffic over HTTPS (TLS 1.2+)
- [x] **SEC-02**: Input validation and sanitization on all endpoints
- [x] **SEC-03**: SQL injection prevention via parameterized queries (sqlc)
- [x] **SEC-04**: File upload validation: type checking, size limits, magic byte verification, UUID filenames
- [x] **SEC-05**: Content-Disposition: attachment on file downloads to prevent content sniffing
- [x] **SEC-06**: CORS restricted to app domain only
- [x] **SEC-07**: OTP brute force protection (rate limiting + attempt limiting)
- [x] **SEC-08**: Per-client file storage limits

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Desktop-optimized UI | Mobile-only design per PRD; YAGNI |
| Multi-language / i18n | Persian-only; target audience is Iranian |
| Real-time video/voice consultation | High complexity, not core value |
| Payment processing / billing | No financial transactions in v1 |
| Wearable / health device integration | High complexity, low priority |
| AI-powered diet recommendations | Explicitly excluded in PRD non-goals |
| Calorie auto-detection from photos | Explicitly excluded in PRD non-goals |
| OAuth / social login | Email/password + OTP sufficient for target users |
| Native mobile app | PWA covers all requirements |
| Real-time WebSocket chat | Polling sufficient per PRD Decision #7 |
| Redis / caching layer | PostgreSQL sufficient at target scale |
| Microservices architecture | Monolith appropriate for scale |
| Recipe management | Not part of nutritionist workflow |
| Grocery list generation | Adds complexity without core value |
| Social features / gamification | Not aligned with professional tool positioning |
| Detailed micronutrients beyond fiber/sugar/sodium | Diminishing returns; can add later |
